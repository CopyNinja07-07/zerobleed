# ZeroBleed results report

Generated by `npm run report` from the raw files in [`evidence/`](evidence/). Every number below is computed from those files; nothing is typed by hand.

## How to check these results are real

1. **Model calls.** Each run has a `*.calls.json` file listing every model call with the model name, the token usage Nightshift reported, and the Nightshift **receipt ID**. Open Nightshift's **Receipts** view and look up any receipt ID: it shows the same request, model and token counts. Our code cannot write to that view.
2. **Data.** Each fact a decision used is listed with the exact Zetaris SQL that produced it (`evidence` in `*.calls.json`). Run the same SQL in the Zetaris SQL Editor at http://localhost:3000 and you get the same value.
3. **Steps.** Each run has a `*.trace.jsonl` file: one line per planner, worker, gate, guard, Markovian chunk and decision, with timestamps and models.
4. **Reproduce.** `npm run benchmark -- procurement 1` and `npm run benchmark -- incident 1`, then `npm run report`. Models can vary slightly between runs; the correct answers are fixed in `src/domains/*.ts`.

Failures stay in the denominator. Token counts are input tokens as reported by Nightshift, which include Nightshift's own per-request overhead for both systems alike.
